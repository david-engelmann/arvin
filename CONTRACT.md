# Contract

Deadman asks whether a runaway agent run can be halted in stages, with every stage named and the reason recorded, before its spend or its actions pass the point where stopping still matters. This file is the stub contract for the setup slice. It states the setup obligations only, and each obligation is stated so it can fail.

Obligation S1 covers seed integrity. The seed files README.md and LICENSE and .gitignore are present from the first commit, and every later change lands through a pull request rather than a direct push to main. This is covered by inspection of the repository history and by the status section of the README.

Obligation S2 covers the local gate. The test suite runs with cargo test plus the codepoint scan run through cargo, and running it needs no paid service, and the continuous integration workflow runs the same commands as the local gate. This wording is amended by the Rust port that opens Round 2. The setup wording named python and pytest alone and no network access, and the amendment replaces it under the program language ruling of 2026-11-02, which made every repo in the program a Rust crate. The amended gate keeps the no paid service term. It drops the no network access term for one stated reason, a first build fetches the crate dependencies from the public crates.io registry, and the tests themselves then run with no network access. This is covered by the tests in the tests folder and by the workflow in the .github folder.

Obligation S3 covers honest status. The README status section records the seed state and the contract state truthfully and it reports closed perfection rounds as 0 of 100 until a full cycle of work and audit and review and red team and approval has closed. This is covered by inspection of the README against this contract and against the repository history.

Obligation S4 covers synthetic content only. Every fixture and every example in this repository is synthetic and written for this repo, and no file carries a real trace or a real transcript or a real name or any private operational detail. This is covered by inspection of the repository contents before any push.

Obligation S5 covers the canonical agents file. The part of AGENTS.md above the marked line is identical to the canonical template for the program, and only the repo annex below the marked line differs for deadman. This is covered by tests in the tests folder that pin the SHA-256 digest of the part above the marked line and check the marked line and the annex.

The full contract for deadman is the first build act of this repo and it lands with the first slice. This stub is not the full contract, and no feature claim for deadman rests on this stub.

## Round 1 amendment, the staged cutoff, slice 1

The full contract the stub promised is this amendment. It names the stub status text above as the earlier record and supersedes it, and the stub text stands so the record shows both. Obligations S1 to S5 stand unchanged above. The obligations for the staged cutoff are DM-1 to DM-12, and each one is stated so it can fail.

### Probe preamble

The obligations below rest on behaviour probed on this machine under Python 3.12.3, not on habit.

Probe one, flock. Eight processes each ran fifty read and modify and write cycles on one shared counter file, holding an exclusive flock on a lock file across each cycle. The counter finished at exactly 400 with zero lost updates. A nonblocking exclusive acquire against a lock another process held raised BlockingIOError. After the holding process was killed, the lock was acquirable again within two milliseconds, so a dead holder cannot wedge the switch.

Probe two, rename. One writer published 300 versions of a JSON document by writing a temporary file in the same directory and renaming it over the target with os.replace. Three reader processes read the document 164033 times in total during the run and saw zero torn or partial documents and zero documents older than one already seen. The state file therefore publishes by rename from a temporary file in its own directory, which also keeps the rename on one device.

### The obligations

Obligation DM-1 covers the stage vocabulary. The stages stand in one exact order, none and warn and throttle and cut tools and cut budget and kill, and no stage is ever renamed, reordered, added, or dropped by this slice. Every stage the switch reports and every stage the state file records is one of those six names. This is covered by tests that read the vocabulary from the code and drive a run through every stage and read each name back from the state file and from the command line.

Obligation DM-2 covers signal intake. A run is opened by registration with a run id, a proof interval in seconds, a missed proof limit, and a soft ceiling and a hard ceiling in the host's own spend units, either of which may stand unset. The defaults are a proof interval of 60 seconds and a missed proof limit of 5, and a run may declare its own values at registration. A proof records a progress proof for a run at an instant with a short note, and the last proof instant of a run never moves backwards, so a late proof carrying an older instant changes nothing about freshness. Freshness before the first proof counts from the registration instant. A spend report adds a nonnegative amount to the accumulated spend of a run. Proofs and spend reports change signals only, and the recorded stage moves only at an evaluation or at a pull. This is covered by tests that register runs with default and declared thresholds, post proofs out of order, and read the accumulated spend and the untouched stage back.

Obligation DM-3 covers the warrants. At any evaluation instant the warranted stage is the highest stage any live trigger warrants. An operator pull warrants kill. Accumulated spend at or above the hard ceiling warrants kill, and accumulated spend at or above the soft ceiling warrants at least cut budget, with equality counting as at the ceiling in both cases. Missed proofs warrant by whole missed intervals past the last proof instant plus the proof interval, where an evaluation exactly at a deadline misses nothing, one missed interval warrants warn, two warrant throttle, three warrant cut tools, four warrant cut budget, any higher count below the missed proof limit still warrants cut budget, and a count at or above the missed proof limit warrants kill. The reasons an evaluation reports are drawn from exactly four names, operator pull and hard ceiling and soft ceiling and missed proofs, and name every trigger live at that instant. This is covered by tests that drive each trigger alone and in combination at injected instants, at the exact ceiling amounts and at the exact deadline instants and one second past them.

Obligation DM-4 covers movement and the latch. The recorded stage rises immediately to the warranted stage at an evaluation, jumping stages when a hard trigger warrants the jump. The recorded stage falls only by hysteresis, where two consecutive evaluations at which the warranted stage stands below the recorded stage step the recorded stage down by exactly one stage, and the count of consecutive lower evaluations resets whenever the warranted stage meets or rises above the recorded stage. The kill stage never falls and never unlatches, whether it was reached by a pull or by a trigger. This is covered by tests that hold a stage through one clear evaluation, step it down on the second, reset the count with a fresh warrant, and drive a killed run with clear evaluations and fresh proofs.

Obligation DM-5 covers the closed run. A killed run is closed. Proofs and spend reports posted to a closed run are recorded as no-ops that change no signal and no stage, because late reports from a dying run are expected traffic and not errors. A pull against a closed run changes nothing and records nothing. An evaluation of a closed run reports kill and changes nothing. The document of a closed run grows only by the recorded no-op reports. This is covered by tests that post proofs and spend and a pull and evaluations to a killed run and read the signals and the log back.

Obligation DM-6 covers time as an input and determinism. Every library operation but one takes the current instant as an explicit argument, and the command line passes the wall clock in UTC and offers no flag that overrides it. The log operation is the one exception, and it returns the recorded log without evaluating anything and so takes no instant. The library reads no wall clock and makes no model calls, and no randomness reaches a stage or a reason or a record or the state bytes, and the one random draw the library makes stands outside that scope and names the temporary file a publication writes before it is renamed over the state file. Given the same state file and the same instant, an evaluation returns the same stage and the same reasons and appends the same record. This is covered by tests that repeat evaluations against copies of one state file and compare the reports and the records, and by a command line test that the surface carries no time override flag.

Obligation DM-7 covers the decision log. The decision log of a run lives inside the same state document as the run, so a stage change and its record publish in the same rename and can never disagree. Log records carry a sequence number that starts at 1 for the registration record and grows by 1 with no gaps, a kind drawn from registered and proof and spend and pull and stage, the instant of the event, the recorded stage standing after the event, the reasons drawn from the four trigger names of DM-3, and three reserved fields named model name and model confidence and fallback taken. An evaluation appends a stage record whenever the recorded stage changes and whenever a live trigger warrants the stage the run already stands at, and an evaluation that only advances the fall count of DM-4 appends nothing. In this slice the three reserved fields stand empty in every record, and a document carrying a value in one of them is refused on reading, because the decision model slice that fills them retires that refusal by amendment when it lands. This is covered by tests that walk a run through registration and proofs and spend and a pull and evaluations and read the log back at each step, and by tests that read the written state file and check the reserved fields stand empty.

Obligation DM-8 covers strict reading. The state is one JSON document under the format name deadman-state/1, and reading it refuses duplicate keys at any level, a wrong format name, a wrong type in any field, and any unknown field, each as a typed corruption error and never a traceback and never a silent repair. The reading also refuses a stage outside the vocabulary of DM-1, a reason outside the four names of DM-3, a log sequence with a gap, a soft ceiling standing above a hard ceiling, and a killed flag that disagrees with the recorded stage. A state file that cannot be read blocks every operation, reads included, and no operation resets it or writes over it. This is covered by a damage battery that corrupts the document in each named way and checks the error type and that the state bytes stand unchanged afterwards.

Obligation DM-9 covers name and value validation. A run id is one component of ASCII lowercase letters and ASCII digits and hyphens and underscores, starting and ending with an ASCII lowercase letter or an ASCII digit, at most 64 characters long, and any other shape is refused at every operation that takes the id. A proof interval is a positive integer number of seconds and at most 86399999999999 seconds, the widest interval the runtime can hold as a duration, and an interval above that bound is refused at registration. A missed proof limit is a positive integer and at most 1000000, and a stored missed proof limit above that bound is refused on reading as corruption, a ceiling is a nonnegative integer or unset and at most 1000000000000000000, and a stored ceiling above that bound is refused on reading as corruption, a soft ceiling standing above a hard ceiling is refused at registration, a spend amount is a nonnegative integer and at most 1000000000000000000, the accumulated spend of a run never stands above that same bound, a stored spend total above the bound is refused on reading as corruption, and a proof note is a string of at most 200 characters, and any other value is refused before any state changes. This is covered by edge tests on both sides of each part of each rule.

Obligation DM-10 covers atomic publication. Every mutating operation runs its whole read and evaluate and modify and write cycle under one exclusive flock on the lock file beside the state file, and the new state is published by renaming a complete temporary file over the state file. Parallel proofs and spend reports against one run lose no updates, and parallel evaluations of one run at one instant report one stage and append no two different outcomes. This is covered by concurrency tests that race processes on proofs and spend against one run and race evaluations at one escalation instant.

Obligation DM-11 covers registration and missing state. Registering a run id that already stands in the state file fails, whether the standing run is live or closed, so one id never carries two runs and a closed run is never reopened under its id. Every operation against a run the state file does not hold fails as not found. When the state file does not stand, the log of any run fails as not found and creates nothing, and the first mutating operation creates the state file and any missing parent directories and then proceeds. This is covered by tests that register one id twice, drive every operation against an unknown id, and read and then mutate against a path where nothing stands yet.

Obligation DM-12 covers the slice 1 limits, stated so a later slice retires them by amendment rather than by drift. The switch decides and records and does not enforce, and no process is signalled or throttled or killed by this slice, because hosts poll the stage and enforce it against their own processes. Proof content is never judged, and a wedged agent posting empty proofs on a timer defeats the freshness checks of this slice, because content judgement belongs to the decision model slice the roadmap describes. The evaluator is deterministic code only and no model is called. The state lives on one machine in one file for callers who share the filesystem, with no network service and no dashboard. A killed run is never reset automatically, and an operator starts a new run under a new id. This is covered by inspection of the slice against this list.

### Repair note, the Round 1 review fixes

This note records the repair pass that answered the three reviews of this slice, and it stands as part of the contract record for the round.

The red team found that a stored log record whose kind holds a list or an object escaped reading as an unhandled TypeError, because the kind was tested for membership in the recorded kinds before its type was checked, while DM-8 promises a typed corruption error for a wrong type in any field. The reader now checks the kind is text before the membership test, and the damage battery carries both shapes.

The red team also found that extreme values escaped the typed errors this contract promises. A proof interval past the widest duration the runtime can hold was accepted at registration and raised an unhandled overflow at evaluation, an instant whose UTC form stands outside the recordable range raised the same overflow while it was formatted for the record, and a spend amount carrying thousands of digits raised an unhandled conversion error at publication while a stored spend total of that size raised it again at reading. DM-9 now states the proof interval ceiling and the spend bound. Registration refuses an interval above the ceiling as a request error, a spend report refuses an amount above the bound and any report that would carry the accumulated spend past it, the reader refuses a stored spend total above the bound as corruption, and the instant formatting and the missed proof arithmetic convert any overflow that remains into a request error, so no accepted input raises a raw overflow or a raw conversion error later.

DM-6 stands amended in two places by this pass. Its opening claim now names the log operation as the one operation that takes no instant, because the log returns recorded state without evaluating anything. Its randomness claim now covers only what reaches a stage or a reason or a record or the state bytes, and the draw that names the temporary file of a publication stands named inside DM-6 as the one draw outside that scope.

Two observations from the red team are recorded here as named residuals for later slices, accepted for this slice and not repaired by this pass. Evaluation instants are host inputs and nothing in this slice orders them, so the instants recorded in a log are not monotonic across evaluations, and a host that evaluates out of order keeps a log that reads out of order. The reader validates every field of every record and of the standing run, and it does not cross validate the history in the log against the standing fields of the run, so a document whose recorded history disagrees with its standing stage is read as it stands.

A follow-up to this pass closed the same escape in the integer registration fields the repair had left unbounded on the write side. A missed proof limit or a soft or a hard ceiling carrying thousands of digits passed the field validation and raised the raw conversion error inside publication, while a stored value past a bound was refused only for the spend total. DM-9 now states the missed proof limit bound of 1000000 and the ceiling bound of the spend bound. Registration refuses a missed proof limit above its bound and a ceiling above the spend bound as request errors, with the value in each refusal message guarded so a value too large to print cannot raise inside the refusal itself, and the reader refuses a stored missed proof limit or a stored ceiling above its bound as corruption, matching the stored spend total.

## Port amendment, the Rust conversion opening Round 2

Amendment, recorded with the Rust port that opens Round 2. The obligations DM-1 to DM-12 above stand unedited, and the implementation that carries them changes. The Python package of Round 1 is replaced by a Rust crate. The library carries the state file, the signal intake, the deterministic stage evaluator with its hysteresis, the spend accounting, and the decision log. The deadman binary carries the command line with the Python surface, the same subcommands and stdout lines and error lines and exit codes, and its argument parser mirrors the Python parser down to its usage texts and its parser error messages and its acceptance of unambiguous option prefixes. The codepoint scanner is ported from the fleet template in std only Rust. Obligation S2 is amended inside its own paragraph above, in the form the conversion of deadbolt set, with the program language ruling of 2026-11-02 named as its reason.

The equivalence standard for the port is threefold. The Round 1 test suite is translated pin for pin into the Rust suite, at the counts the Python suite collects on main, 101 protocol pins and 21 setup pins, counted by collection before the port was written. Ten state files written by the Python implementation stand frozen in the tests fixtures folder with a manifest that records their hashes and their decision log lines and their stage truths at named instants, and the Rust suite reads each one and checks the log and the stage against the record, replays every production operation and compares the written state byte for byte, and continues three of the fixtures under Rust against continuation files the Python implementation produced from the same fixtures. A fixed battery of command line shapes is driven side by side under the Python implementation from main and under the Rust port, with exit codes and stdout and stderr and the state bytes compared shape by shape, and the comparison is recorded in the gate report of the port pull request.

The port adds a thin PyO3 binding over the crate as the round's second slice, landed separately after the port, because agent hosts that poll the switch for a stage are often Python, while the port pull request itself carries no binding and the Rust suite remains the gate.

Reshapings are named here, because the obligations and the observable behaviour are the spec and the shape of the Python code is not. The strict reader is a hand written reader over the document bytes in place of the Python json module. It refuses a repeated key at any level as the key arrives, because a general reader that keeps the last value of a repeated key and says nothing cannot carry DM-8. It holds an integer of any width as its canonical decimal text, so the bounds of DM-9 judge the same values the Python reader judged, and it applies the same 4300 digit parse limit the Python reader applies to an integer literal. It decodes the byte encodings the Python reader detects, UTF-8 and UTF-16 and UTF-32 with and without a byte order mark, by the same first bytes rule the Python reader uses. It bounds the nesting depth it will read, and a document nested past the bound is refused as not parsing. The document writer is hand rolled over the fixed shape of the format and reproduces the Python byte layout, its indentation and its construction key order and its escaping of non ASCII text, because the stored bytes are part of the recorded behaviour. Instants are parsed and written by a hand written reader and writer in place of the Python datetime machinery. The stored instant family the reader accepts is the family the Python fromisoformat accepted, as probed against the Python runtime before the port was written. It takes extended and basic and week calendar dates, any single character as the separator between the date and the time, a fraction written with a dot or a comma and truncated past six digits on the time and on the offset, and offsets whose hour and minute and second components normalize inside a day. An offset fraction counts in exactly the cases the Python parser counts it, whenever some whole component of the offset is nonzero, and is dropped in the one case the Python parser drops it, an offset whose whole components are all zero. The reader refuses a naive instant and an unparseable one with the corruption messages the Python reader raised. Names and caller integers are validated through one value level validator that the typed operations and the command line converters and the strict reader all share. The Python implementation validated the values its callers handed it at runtime, and the Rust type system makes most wrong shapes unrepresentable at the typed surface, so the validator is where the refusal lives for the shapes that remain, and the translated pins drive it directly for those shapes. The three process race pins are restaged on operating system processes that reenter the test binary through an environment gate, the shape the language offers for the same claims, and the counts they assert are the counts the Python pins asserted.

Two behaviours are deliberate divergences from the Python original, recorded here with their reasons. The lock a command holds is verified as the file standing at the lock path. Neither the Python original nor this port as first built checked that identity, so deleting the lock file while an operation worked could let a second operation lock a fresh file and publish over the first, erasing a recorded operation without a trace, against the atomicity DM-10 states unconditionally. After the lock is taken its device and inode are checked against the path, with a bounded retry while the path settles, and the identity is checked again immediately before a publish. A command whose held lock is not the file at the path aborts with a failure and leaves the state byte-identical. The invariant is that an operation which exits 0 is recorded, and an operation whose record could be silently erased exits 1 instead. The port closes the hole rather than inheriting it silently. The publish opens its temporary file exclusively, so a plant standing at the temporary name, a symlink to a victim file among them, fails the publish instead of being followed and written through, where the Python open truncates what stands there. The temporary name carries the process id and a random draw from the operating system source, the one draw DM-6 scopes outside the state bytes, so the name cannot be predicted in practice and the difference meets only a staged plant.

Two further differences are recorded here as safe direction divergences. The detail text of a document that does not parse, and of a state file that cannot be read, comes from the parser and the system layer each implementation carries, so the words after the shared message head differ while the error classification and the exit code are the same. A stored string carrying an unpaired surrogate escape is read with the replacement character where the Python reader holds the surrogate itself. Every field such a string can stand in is refused by the reading validation of both implementations, so only the rendering of the value inside a refusal message differs. A value carrying a codepoint with no assigned character renders as the character itself where the Python repr escapes it, because the unassigned ranges cannot be enumerated inside the crate. That difference is confined to the same place, the rendering of a value inside a refusal message, and the refusal itself and its exit code are the same.
