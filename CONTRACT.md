# Contract

Deadman asks whether a runaway agent run can be halted in stages, with every stage named and the reason recorded, before its spend or its actions pass the point where stopping still matters. This file is the stub contract for the setup slice. It states the setup obligations only, and each obligation is stated so it can fail.

Obligation S1 covers seed integrity. The seed files README.md and LICENSE and .gitignore are present from the first commit, and every later change lands through a pull request rather than a direct push to main. This is covered by inspection of the repository history and by the status section of the README.

Obligation S2 covers the local gate. The test suite runs with python and pytest alone and running it needs no network access and no paid service, and the continuous integration workflow runs the same commands as the local gate. This is covered by the tests in the tests folder and by the workflow in the .github folder.

Obligation S3 covers honest status. The README status section records the seed state and the contract state truthfully and it reports closed perfection rounds as 0 of 100 until a full cycle of work and audit and review and red team and approval has closed. This is covered by inspection of the README against this contract and against the repository history.

Obligation S4 covers synthetic content only. Every fixture and every example in this repository is synthetic and written for this repo, and no file carries a real trace or a real transcript or a real name or any private operational detail. This is covered by inspection of the repository contents before any push.

Obligation S5 covers the canonical agents file. The part of AGENTS.md above the marked line is identical to the canonical template for the program, and only the repo annex below the marked line differs for deadman. This is covered by tests in the tests folder that pin the SHA-256 digest of the part above the marked line and check the marked line and the annex.

The full contract for deadman is the first build act of this repo and it lands with the first slice. This stub is not the full contract, and no feature claim for deadman rests on this stub.

## Round 1 amendment, the staged cutoff, slice 1

The full contract the stub promised is this amendment. It names the stub status text above as the earlier record and supersedes it, and the stub text stands so the record shows both. Obligations S1 to S5 stand unchanged above. The obligations for the staged cutoff are DM-1 to DM-12, and each one is stated so it can fail.

### Probe preamble

The obligations below rest on behaviour probed on this machine under Python 3.12.3, not on habit.

Probe one, flock. Eight processes each ran fifty read and modify and write cycles on one shared counter file, holding an exclusive flock on a lock file across each cycle. The counter finished at exactly 400 with zero lost updates. A nonblocking exclusive acquire against a lock another process held raised BlockingIOError. After the holding process was killed, the lock was acquirable again within two milliseconds, so a dead holder cannot wedge the switch.

Probe two, rename. One writer published 300 versions of a JSON document by writing a temporary file in the same directory and renaming it over the target with os.replace. Three reader processes read the document 164033 times in total during the run and saw zero torn or partial documents and zero documents older than one already seen. The state file therefore publishes by rename from a temporary file in its own directory, which also keeps the rename on one device.

### The obligations

Obligation DM-1 covers the stage vocabulary. The stages stand in one exact order, none and warn and throttle and cut tools and cut budget and kill, and no stage is ever renamed, reordered, added, or dropped by this slice. Every stage the switch reports and every stage the state file records is one of those six names. This is covered by tests that read the vocabulary from the code and drive a run through every stage and read each name back from the state file and from the command line.

Obligation DM-2 covers signal intake. A run is opened by registration with a run id, a proof interval in seconds, a missed proof limit, and a soft ceiling and a hard ceiling in the host's own spend units, either of which may stand unset. The defaults are a proof interval of 60 seconds and a missed proof limit of 5, and a run may declare its own values at registration. A proof records a progress proof for a run at an instant with a short note, and the last proof instant of a run never moves backwards, so a late proof carrying an older instant changes nothing about freshness. Freshness before the first proof counts from the registration instant. A spend report adds a nonnegative amount to the accumulated spend of a run. Proofs and spend reports change signals only, and the recorded stage moves only at an evaluation or at a pull. This is covered by tests that register runs with default and declared thresholds, post proofs out of order, and read the accumulated spend and the untouched stage back.

Obligation DM-3 covers the warrants. At any evaluation instant the warranted stage is the highest stage any live trigger warrants. An operator pull warrants kill. Accumulated spend at or above the hard ceiling warrants kill, and accumulated spend at or above the soft ceiling warrants at least cut budget, with equality counting as at the ceiling in both cases. Missed proofs warrant by whole missed intervals past the last proof instant plus the proof interval, where an evaluation exactly at a deadline misses nothing, one missed interval warrants warn, two warrant throttle, three warrant cut tools, four warrant cut budget, any higher count below the missed proof limit still warrants cut budget, and a count at or above the missed proof limit warrants kill. The reasons an evaluation reports are drawn from exactly four names, operator pull and hard ceiling and soft ceiling and missed proofs, and name every trigger live at that instant. This is covered by tests that drive each trigger alone and in combination at injected instants, at the exact ceiling amounts and at the exact deadline instants and one second past them.

Obligation DM-4 covers movement and the latch. The recorded stage rises immediately to the warranted stage at an evaluation, jumping stages when a hard trigger warrants the jump. The recorded stage falls only by hysteresis, where two consecutive evaluations at which the warranted stage stands below the recorded stage step the recorded stage down by exactly one stage, and the count of consecutive lower evaluations resets whenever the warranted stage meets or rises above the recorded stage. The kill stage never falls and never unlatches, whether it was reached by a pull or by a trigger. This is covered by tests that hold a stage through one clear evaluation, step it down on the second, reset the count with a fresh warrant, and drive a killed run with clear evaluations and fresh proofs.

Obligation DM-5 covers the closed run. A killed run is closed. Proofs and spend reports posted to a closed run are recorded as no-ops that change no signal and no stage, because late reports from a dying run are expected traffic and not errors. A pull against a closed run changes nothing and records nothing. An evaluation of a closed run reports kill and changes nothing. The document of a closed run grows only by the recorded no-op reports. This is covered by tests that post proofs and spend and a pull and evaluations to a killed run and read the signals and the log back.

Obligation DM-6 covers time as an input and determinism. Every library operation takes the current instant as an explicit argument, and the command line passes the wall clock in UTC and offers no flag that overrides it. The library reads no wall clock, draws no randomness, and makes no model calls. Given the same state file and the same instant, an evaluation returns the same stage and the same reasons and appends the same record. This is covered by tests that repeat evaluations against copies of one state file and compare the reports and the records, and by a command line test that the surface carries no time override flag.

Obligation DM-7 covers the decision log. The decision log of a run lives inside the same state document as the run, so a stage change and its record publish in the same rename and can never disagree. Log records carry a sequence number that starts at 1 for the registration record and grows by 1 with no gaps, a kind drawn from registered and proof and spend and pull and stage, the instant of the event, the recorded stage standing after the event, the reasons drawn from the four trigger names of DM-3, and three reserved fields named model name and model confidence and fallback taken. An evaluation appends a stage record whenever the recorded stage changes and whenever a live trigger warrants the stage the run already stands at, and an evaluation that only advances the fall count of DM-4 appends nothing. In this slice the three reserved fields stand empty in every record, and a document carrying a value in one of them is refused on reading, because the decision model slice that fills them retires that refusal by amendment when it lands. This is covered by tests that walk a run through registration and proofs and spend and a pull and evaluations and read the log back at each step, and by tests that read the written state file and check the reserved fields stand empty.

Obligation DM-8 covers strict reading. The state is one JSON document under the format name deadman-state/1, and reading it refuses duplicate keys at any level, a wrong format name, a wrong type in any field, and any unknown field, each as a typed corruption error and never a traceback and never a silent repair. The reading also refuses a stage outside the vocabulary of DM-1, a reason outside the four names of DM-3, a log sequence with a gap, a soft ceiling standing above a hard ceiling, and a killed flag that disagrees with the recorded stage. A state file that cannot be read blocks every operation, reads included, and no operation resets it or writes over it. This is covered by a damage battery that corrupts the document in each named way and checks the error type and that the state bytes stand unchanged afterwards.

Obligation DM-9 covers name and value validation. A run id is one component of lowercase letters and digits and hyphens and underscores, starting and ending with a letter or a digit, at most 64 characters long, and any other shape is refused at every operation that takes the id. A proof interval is a positive integer number of seconds, a missed proof limit is a positive integer, a ceiling is a nonnegative integer or unset, a soft ceiling standing above a hard ceiling is refused at registration, a spend amount is a nonnegative integer, and a proof note is a string of at most 200 characters, and any other value is refused before any state changes. This is covered by edge tests on both sides of each part of each rule.

Obligation DM-10 covers atomic publication. Every mutating operation runs its whole read and evaluate and modify and write cycle under one exclusive flock on the lock file beside the state file, and the new state is published by renaming a complete temporary file over the state file. Parallel proofs and spend reports against one run lose no updates, and parallel evaluations of one run at one instant report one stage and append no two different outcomes. This is covered by concurrency tests that race processes on proofs and spend against one run and race evaluations at one escalation instant.

Obligation DM-11 covers registration and missing state. Registering a run id that already stands in the state file fails, whether the standing run is live or closed, so one id never carries two runs and a closed run is never reopened under its id. Every operation against a run the state file does not hold fails as not found. When the state file does not stand, the log of any run fails as not found and creates nothing, and the first mutating operation creates the state file and any missing parent directories and then proceeds. This is covered by tests that register one id twice, drive every operation against an unknown id, and read and then mutate against a path where nothing stands yet.

Obligation DM-12 covers the slice 1 limits, stated so a later slice retires them by amendment rather than by drift. The switch decides and records and does not enforce, and no process is signalled or throttled or killed by this slice, because hosts poll the stage and enforce it against their own processes. Proof content is never judged, and a wedged agent posting empty proofs on a timer defeats the freshness checks of this slice, because content judgement belongs to the decision model slice the roadmap describes. The evaluator is deterministic code only and no model is called. The state lives on one machine in one file for callers who share the filesystem, with no network service and no dashboard. A killed run is never reset automatically, and an operator starts a new run under a new id. This is covered by inspection of the slice against this list.
